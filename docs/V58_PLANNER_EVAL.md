# V58 route planner replay evaluator

Run `python3 experiments/v58_planner_eval/evaluate_replays.py replay.json ... --seat N` to compare route-planner replays without rerunning matches. The action on replay frame `i` is evaluated against frame `i-1`'s observation, matching the engine's action/observation order. Output includes per-actor non-pass actions with an observed effect, hand productive turns/rate, FEED attempt and precondition success counts, observed daily opening/closing cash, animals lost at day boundaries, and sales estimates.

The replay JSON does not include market commit logs. `accepted_sales_lower_bound_units` therefore counts only requested sale units that appear as a net drop in the player's carried plus shed inventory between adjacent observations, capped by the submitted quantity. Concurrent production, consumption, or other same-turn inventory flows can make this estimate undercount or misattribute sales; treat it as a screening metric, not authoritative engine acceptance. The corresponding value estimate uses the pre-action observed market price. When `market_commits` are available in a separate audit artifact, prefer those records for exact accepted quantity and money delta.

`valid_actor_actions_observed` uses local actor evidence (position movement, tile change, or that actor's carried inventory change); it does not reconstruct all engine legality rules. It is useful for finding routes where hands mostly pass or fail to make observable progress. Feed validation is explicit from the pre-action animal tile, fed flag, and carried wheat. Compare candidates on the same disjoint seeds from 94600 onward and both seat orders; retain per-seed and per-seat values rather than only aggregate averages. This directory is an analysis aid only and does not modify the frozen or submitted agent.
